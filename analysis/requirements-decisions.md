# Зафиксированная основа требований MAG8000-LTE

Статус: SOURCE_BASELINE_ACCEPTED.

## Источник и объём

Единственный источник требований — `source/MAG8000-LTE-FeatureSpecReqBL4.reqif`, экспорт Polarion `feature specification baseline 4`.

- Все 70 объектов Polarion типа `Feature` входят в объём анализа.
- Все 32 объекта `Heading` и исходная иерархия разделов сохраняются.
- Ни один Feature не исключается из-за пометок Release 1 / Release 2, nice-to-have, to be discussed или needs to be discussed.
- Исходные Polarion IDs и ReqIF UUID сохраняются для прослеживаемости.
- Тексты исходника не переписываются и не дополняются предположениями.

## Особенности исходных данных

1. У 68 Feature заполнен `ReqIF.Text`.
2. У двух Feature (`adr-10361`, `adr-10363`) `ReqIF.Text` пуст. Их `ReqIF.ChapterName` сохранён отдельно и не подменяет пустое поле.
3. В экспорте присутствуют 26 отношений `fulfills`. У всех SOURCE разрешается, TARGET отсутствует среди 102 экспортированных SpecObject. Все записи остаются в инвентаризации как неразрешённые.
4. В документе упоминаются внешние технические документы, но их содержимое не входит в экспорт. Используются только сведения, реально присутствующие в ReqIF.
5. Упоминание customer через Web APP не превращается в прямую связь человека с 4G module.

## Прямые C1-взаимодействия

В `RequirementsAnalysis.xml` отражены только взаимодействия с явно указанным направлением:

- Web APP → MAG8000-LTE: команда `GET_PARAMETER` для получения параметров (`adr-10353`);
- MAG8000-LTE → MQTT Broker: отправка тревог с временными метками (`adr-10341`);
- thingstream server → MAG8000-LTE: предоставление UNIX-UTC времени для синхронизации часов (`adr-10406`).

Человеческие акторы и AAG use cases, непосредственно связывающие человека с MAG8000-LTE, исходным ReqIF явно не определены; такие связи не создаются.

## Правило преобразования в GRACE

- Полный исходный реестр 70 Feature, 32 Heading и 26 отношений хранится в `analysis/reqif-inventory.md`; оригинал сохранён в `source/`.
- `RequirementsAnalysis.xml` использует только конструкции, определённые GRACE и GRACE-ARP. Неподтверждённые сущности и отношения не добавляются.
- Polarion `Feature` не переименовывается автоматически в Actor, Use Case, Business Process, Invariant или External System.
- Семантическая классификация выполняется только там, где её поддерживает содержание источника. Остальные требования сохраняются без искусственного назначения типа.
- `source/MAG8000-LTE-FeatureSpecReqBL4.reqif` остаётся неизменным оригиналом.

# Зафиксированная основа требований MAG8000-LTE

Статус: SOURCE_BASELINE_ACCEPTED.

## Источник и объём

Единственный источник требований — `source/MAG8000-LTE-FeatureSpecReqBL4.reqif`, экспорт Polarion `feature specification baseline 4`.

- Все 70 объектов Polarion типа `Feature` входят в объём анализа.
- Все 32 объекта `Heading` и исходная иерархия разделов сохраняются.
- Ни один Feature не исключается из-за пометок Release 1 / Release 2, nice-to-have, to be discussed или needs to be discussed. Эти пометки сохраняются как часть исходного содержания.
- Исходные Polarion IDs и ReqIF UUID сохраняются для прослеживаемости.
- Тексты не переписываются и не дополняются предположениями.

## Особенности исходных данных

1. У 68 Feature заполнен `ReqIF.Text`.
2. У двух Feature (`adr-10361`, `adr-10363`) `ReqIF.Text` пуст. Их `ReqIF.ChapterName` сохранён отдельно; значение не подменяется незаметно.
3. В экспорте присутствуют 26 отношений `fulfills`. Все исходные записи сохраняются. У всех 26 SOURCE разрешается, TARGET отсутствует среди 102 экспортированных SpecObject.
4. В документе упоминаются внешние технические документы, но их содержимое не входит в экспорт. Используются только сведения, реально присутствующие в ReqIF.
5. Упоминание customer через Web APP не превращается в прямую связь человека с 4G module.
6. C1-взаимодействия отражают только прямые указания источника:
   - Web APP → MAG8000-LTE: команда `GET_PARAMETER` для получения параметров (`adr-10353`);
   - MAG8000-LTE → MQTT Broker: отправка тревог с временными метками (`adr-10341`);
   - Thingstream server → MAG8000-LTE: предоставление UNIX-UTC времени для синхронизации часов (`adr-10406`).

## Правило преобразования в GRACE

- `RequirementsAnalysis.xml` содержит минимальную цель, явно подтверждённые C1-взаимодействия и полный исходный реестр Feature/Heading/relations как отдельный provenance-слой.
- Нельзя преобразовывать Polarion `Feature` в Actor, Use Case, Business Process, Invariant или External System только по названию или грамматической форме.
- Семантическая классификация выполняется только там, где её поддерживает содержание источника. Неразрешённые сведения сохраняются как неразрешённые, а не заполняются догадками.
- `source/MAG8000-LTE-FeatureSpecReqBL4.reqif` остаётся неизменным оригиналом.

# 13. Агентно-доступная тестовая поверхность

Приложение должно предоставлять агенту не только GUI, но и:

- CLI;
- API;
- Tools;
- получение состояния;
- получение трасс;
- сброс тестовой среды;
- загрузку контрольных данных.

Примеры предметных инструментов:

```text
create_order
validate_order
reserve_stock
post_document
get_order_state
get_trace
find_events
reset_test_environment
```

Схема:

```text
Тестовый агент
→ Tool Gateway / CLI
→ тестовая среда
→ приложение
→ состояние + логи + трасса
```

Преимущества:

- агент работает с бизнес-операциями, а не инфраструктурой GUI;
- сценарии короче;
- результат воспроизводим;
- легче извлекать проблемные данные;
- проще локализовать этап;
- тестовый код не перегружает рабочий контекст.

GUI-тесты сохраняются для пользовательских E2E-сценариев, но не должны быть единственным способом проверки.

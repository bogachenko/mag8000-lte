## 12.6. Формальная проверка автоматных моделей

Для каждой автоматной спецификации, созданной по оценке `REQUIRED`, модель должна проходить структурные проверки полноты, непротиворечивости и детерминированности. В частности, проверяется, что для одной комбинации состояния, события и контекста не могут одновременно выбираться несколько переходов без явно заданного приоритета; обработка события при отсутствии подходящего перехода определена; порядок обработки событий и выполнения действий не зависит от незафиксированной гонки. Если выбранный в проекте инструментарий поддерживает Model Checking для используемой модели, заданные формальные свойства должны проверяться этим методом.

В зависимости от модели проверяемые свойства могут включать:

- отсутствие неоднозначных или конфликтующих переходов при одинаковых состоянии, событии и контексте;
- взаимную исключительность guards либо корректность заданного приоритета;
- полноту политики обработки событий, для которых нет подходящего перехода;
- соблюдение заданного порядка обработки событий и выполнения действий;
- недостижимость запрещённых состояний;
- сохранение инвариантов при всех допустимых переходах;
- отсутствие запрещённых переходов;
- достижимость состояний, достижение которых обязательно;
- отсутствие тупиковых состояний, если они запрещены требованиями;
- выполнение заданных ограничений на последовательности событий.

Результат должен ссылаться на версию `AUTOMATON_SPEC`, проверенные свойства, настройки и версию инструмента. Если Model Checking не выполнялся или инструмент не поддерживает модель, это явно фиксируется; обычные тесты не объявляются эквивалентом Model Checking.

Model Checking проверяет модель, а не автоматически сгенерированный или вручную написанный исходный код. Соответствие реализации модели является отдельной проверкой этапа 8 GRACE.

# 8. Семантическая разметка и якоря

Семантическая разметка имеет двойное назначение.

Для генеративной LLM она:

- является top-down шаблоном;
- материализует план;
- уменьшает произвольность;
- дробит большую задачу на локальные спецификации.

Для RAG-агента она:

- является индексом;
- предоставляет стабильные координаты;
- позволяет быстро собрать контекст;
- помогает точно применить патч.

Гранулярность должна быть пропорциональна критичности и сложности. Не нужно размечать каждую строку. Один блок должен решать понятную атомарную задачу.

Для больших контекстов GRACE предпочитает XML, XML-подобные теги, Markdown с явными разделителями и компактные именованные блоки.

JSON сохраняется для API, tool calling, строгих схем, сериализации и программного обмена.

```text
Длинный LLM-контекст → XML-like / Markdown / именованные блоки
Машинный обмен → JSON
```

Преимущества XML-like:

- явные начало и конец блока;
- естественная вложенность;
- теги являются семантическими именами;
- блок легко найти поиском;
- удобно ссылаться на ID;
- удобно применять патчи;
- удобно включать код и документы.

Конкретные объяснения внутренней деградации JSON не являются обязательной частью GRACE. Формат проверяется eval-тестами на целевой модели.

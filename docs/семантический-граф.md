# 3. Семантический граф

LLM в любом случае формирует связи между понятиями. Если инженер не задаёт граф явно, модель строит его по порядку текста, повторению терминов, близости фрагментов и локальной заметности. Такой неявный граф может содержать ошибочные ветви.

В GRACE используется управляемый граф:

```text
Требование
→ бизнес-процесс
→ модуль
→ контракт модуля
→ контракт функции
→ семантический блок кода
→ тест
→ трасса
→ событие лога
```

Большой документ должен иметь два представления:

```text
1. Детальное содержание
2. Компактный семантический граф
```

Граф выполняет функции оглавления, карты навигации, семантического сжатия, системы перекрёстных ссылок, стабильных координат для RAG и каркаса top-down генерации.

Методология пригодна для ИИ, если её можно представить как связный граф:

```text
Цель → входные данные → действия → условия переходов → результаты → проверки
```

Критерии полноценного графа:

- у каждого узла есть самостоятельная функция;
- связи имеют понятный смысл;
- по графу можно воспроизвести процесс;
- у этапов есть проверяемые результаты;
- отсутствуют логические разрывы;
- повторения и риторика не заменяют механизмы.

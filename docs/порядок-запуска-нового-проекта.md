# 24. Порядок запуска нового проекта

1. Провести RequirementsAnalysis.
2. Создать семантический граф требований и бизнес-процессов внутри RequirementsAnalysis.xml.
3. Утвердить граф человеком.
4. Создать Technology.xml.
5. Создать DevelopmentPlan.xml с архитектурным графом и предварительно выделить модули-кандидаты для оценки автоматного программирования.
6. Создать и утвердить контракты модулей с обязательной оценкой применимости автоматного программирования.
7. Для каждой оценки с `REQUIRED` создать, проверить на полноту, непротиворечивость и детерминированность и утвердить соответствующую `AUTOMATON_SPEC`; для `NOT_REQUIRED` спецификацию не создавать, а `UNRESOLVED` разрешить до реализации соответствующего контура (или всего модуля, если контур нельзя изолировать).
8. Создать и утвердить контракты классов и функций, связывая их с одной или несколькими автоматными спецификациями там, где это применимо.
9. Выполнить мысленные сценарии, включая проверку последовательностей событий и переходов для контуров с `REQUIRED`.
10. Определить проверяемые свойства, ожидаемые traces и тестовую поверхность.
11. Сгенерировать или реализовать код по утверждённым контрактам и автоматным спецификациям.
12. Запустить детерминированные, формальные (если применимы), агентные и трассовые проверки.
13. Принять изменение только после полной верификации.

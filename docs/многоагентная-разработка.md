# 17. Многоагентная разработка

Роли должны быть разделены.

## Агент требований

- формализует сценарии;
- строит граф;
- определяет критерии;
- не пишет реализацию.

## Агент архитектуры

- строит DevelopmentPlan.xml;
- определяет модули;
- создаёт контракты верхнего уровня;
- выполняет мысленные тесты.

## Агент тестирования

- выводит проверки из контрактов;
- создаёт сценарии;
- выполняет Tools;
- формирует структурированный feedback;
- не подгоняет критерии под реализацию.

## Агент реализации

- пишет код по утверждённым контрактам;
- не меняет требования и приёмочные критерии самостоятельно.

## Агент-рецензент

- сравнивает патч с контрактами;
- анализирует трассы;
- проверяет побочные эффекты;
- ищет архитектурный дрейф.

## Оркестратор или человек

- утверждает изменения;
- разрешает конфликты;
- принимает решения при изменении замысла;
- контролирует критические операции.

Критическое ограничение:

```text
Один агент не должен бесконтрольно изменять одновременно:
код + контракт + тесты + критерии приёмки
```

Иначе он может устранить не дефект, а сам критерий, обнаруживший дефект.

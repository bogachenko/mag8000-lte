# 18. IDE 2.0 по GRACE

В традиционной IDE основной объект:

```text
файл → класс → метод → строка
```

В IDE, нативной для LLM:

```text
требование → бизнес-процесс → модуль → контракт → функция → код
```

IDE должна:

- показывать семантический граф;
- вычислять последствия изменения;
- находить зависимые узлы;
- обновлять производные контракты;
- показывать изменения человеку;
- регенерировать только затронутые блоки;
- запускать связанные тесты;
- проверять traces;
- сохранять прослеживаемость.

Изменение распространяется сверху вниз:

```text
Требование изменено
→ обновлён бизнес-процесс
→ обновлён архитектурный граф
→ обновлены контракты модулей и оценка применимости автоматов
→ обновлены автоматные спецификации (если затронуты)
→ обновлены контракты функций
→ перегенерирован или скорректирован код
→ обновлены тесты и ожидаемые traces
→ выполнена регрессия
```

Если изменение затрагивает управляющие состояния, события, условия или переходы, необходимо пересмотреть затронутые оценки применимости и согласованность соответствующих `AUTOMATON_SPEC` (одной или нескольких), а затем обновить зависимые контракты, реализацию и проверки. Для модуля с несколькими автоматами обновляется только затронутая спецификация и её зависимая ветвь, если взаимодействие автоматов не требует согласованного изменения нескольких спецификаций. Исправление только реализации, не меняющее утверждённое поведение, не является основанием автоматически менять спецификацию. Одна модель может последовательно обновлять несколько артефактов, но должна соблюдать направление зависимостей и не подгонять верхнеуровневые артефакты под ошибочный код.

Код становится производным артефактом, а контракт — интерфейсом между человеком и системой.

# 5. Процесс разработки по GRACE

## Этап 1. Анализ требований

Первое действие при новом проекте — не выбор стека и не написание кода. Сначала проводится RequirementsAnalysis.

```text
Неформальное описание
→ очистка неоднозначности
→ Actor–Action–Goal
→ бизнес-процессы
→ сущности и состояния
→ правила и инварианты
→ критерии результата
→ семантический граф требований
→ RequirementsAnalysis.xml
→ утверждение человеком
```

Этап завершён, когда можно однозначно ответить:

- кто использует систему;
- что он делает;
- зачем;
- какие сущности участвуют;
- какие состояния меняются;
- что считается успешным результатом;
- какие правила нельзя нарушать;
- какие ошибки и границы предусмотрены;
- как связаны все элементы.

## Этап 2. Выбор технологий

После утверждения требований создаётся Technology.xml.

Нельзя выбирать библиотеку только потому, что модель знает её лучше. Выбор должен следовать из требований, ограничений, среды эксплуатации, совместимости, безопасности, характеристик данных и ожидаемой нагрузки. Если проекту нужны автоматные спецификации, на этом этапе также фиксируются выбранная нотация и доступные средства проверки модели; инструмент генерации кода выбирается только при необходимости.

## Этап 3. Архитектурный граф

На основе требований и технологий создаётся DevelopmentPlan.xml.

Архитектура должна явно показывать:

```text
Бизнес-процесс
→ модуль
→ ответственность
→ данные
→ зависимости
→ состояние
→ инвариант
```

Нельзя начинать с деталей функций и позже пытаться восстановить архитектуру из кода.

На этом этапе архитектурный анализ выделяет модули-кандидаты и, насколько это известно, самостоятельные контуры управляющего поведения внутри них. Один модуль может содержать несколько независимых контуров (например, несколько жизненных циклов). Это предварительный список для проверки в `MODULE_CONTRACT`, а не окончательное решение о применении автоматного программирования. Окончательная оценка выполняется в контракте каждого модуля отдельно для каждого выявленного контура; если контуры не выделены, оценивается модуль в целом.
